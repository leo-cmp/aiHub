# 3.2 — decisions.md (Índice de Decisões)

**Categoria:** Memória e Handoff | **Prioridade:** 🟡 Alta | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Criar índice cronológico de decisões de arquitetura, stack e regras de negócio. Substitui o sistema de `facts[]` do ThreadBridge. Permite que qualquer agente em sessão nova recupere o histórico de "por que decidimos isso".

## Situação Atual

ThreadBridge mantinha `facts[]` com embedding, confidence, provenance — pesado (41KB), externo, sem garantia de disponibilidade. Sem ele, decisões passadas são perdidas entre sessões.

## Especificação

### Arquivo: `src/.ai/decisions.md`

Template vazio (cresce com o tempo):

```markdown
# Índice de Decisões

> Registro cronológico. Nunca remover entradas — riscar se revogada.
> Formato: data, contexto, decisão, rationale, alternativas, impacto.

---

_ Nenhuma decisão registrada ainda. O agente adiciona a primeira entrada ao tomar decisão significativa._
```

### Formato de Entrada

Cada decisão segue este formato fixo:

```markdown
## YYYY-MM-DD HH:mm — Título curto da decisão

**Contexto:** 1-2 linhas sobre o que motivou a decisão.

**Decisão:** O que foi decidido, em termos concretos.

**Rationale:** Por que esta opção e não as alternativas.

**Alternativas consideradas:** Opção X (descartado — motivo curto). Opção Y (descartado — motivo curto).

**Impacto:** O que esta decisão afeta (quais arquivos, guidelines, regras de negócio).
```

### Regras

1. **Nunca remover entradas.** Se uma decisão for revogada, riscar com `~~revogada em YYYY-MM-DD — ver [link]~~` e criar nova entrada.
2. **Máximo 10 linhas por entrada.** Se precisar de mais detalhes, criar `.ai/decisions/<tema>.md` e linkar do índice.
3. **Ordem cronológica reversa** (mais recente no topo).
4. **Agente registra ao tomar decisão**, não depois.

### Mudanças no AGENTS.md

No bloco `## Contexto Base`, adicionar como item 5:
```markdown
5. `.ai/decisions.md` (histórico de decisões de arquitetura/stack/regras)
```

No bloco `## Memória entre Sessões` (criado pelo item 3.1):
```markdown
- Se `.ai/decisions.md` foi alterado, confirme que está atualizado.
```

### Integração com roles

`project-planner`, `technical-lead` e `product-analyst` devem ler `decisions.md` antes de propor mudanças que possam conflitar com decisões anteriores.

Adicionar nas guidelines desses roles:
```markdown
- Leia `.ai/decisions.md` para verificar decisões anteriores que possam afetar esta demanda.
```
