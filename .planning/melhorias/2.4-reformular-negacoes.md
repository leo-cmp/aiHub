# 2.4 — Reformular Negações como Afirmações

**Categoria:** Robustez do Sistema de Regras | **Prioridade:** 🟡 Alta | **Esforço:** M
**Fonte:** DEEPSEEK

## Objetivo

Reformular todas as instruções negativas ("não faça X") como afirmações do comportamento desejado ("faça Y"). LLMs processam negações pior que afirmações — "não use float" ativa os tokens que está tentando suprimir.

## Situação Atual

Múltiplos arquivos usam negação. Exemplos:

| Arquivo | Trecho |
|---------|--------|
| `AGENTS.md:16` | "Nao carregue skills antecipadamente" |
| `execution.md:21` | "NUNCA SUPONHA" |
| `backend-engineer.md:13` | "Nao deve fazer: Usar float para dinheiro" |

## Especificação

### Regra de transformação

```
❌ "Não use X"
✅ "Use Y. X é rejeitado em code review."
```

### Mudanças por arquivo

**`AGENTS.md` — Carregamento de Skills:**
```markdown
# Antes:
**Nao carregue skills antecipadamente.**
# Depois:
**Carregue skills apenas quando explicitamente acionadas** (atalho `/aihub:*`, cargo ativo ou guideline de stack).
```

**`execution.md` — NUNCA SUPONHA:**
```markdown
# Antes:
**NUNCA SUPONHA**: Diante de qualquer ambiguidade...
# Depois:
**PARE E PERGUNTE**: Diante de qualquer ambiguidade...
```

**`backend-engineer.md` — Float:**
```markdown
# Antes:
- Usar `float` para dinheiro.
# Depois:
- Usar tipo inadequado para dinheiro. Use `DECIMAL(15,2)` ou equivalente da stack.
```

**`frontend-engineer.md` — Verificar existência:**
(Verificar se há negações neste arquivo)

**`brainstorming/SKILL.md` — Gate:**
```markdown
# Antes:
Do NOT invoke any implementation skill, write any code, scaffold any project...
# Depois:
Aguarde aprovação do design antes de qualquer implementação.
```

### Padrão geral

Varrer `src/` com:
```bash
grep -rn "não\|nao\|NUNCA\|NOT\|never\|don't" src/ --include="*.md"
```

Para cada ocorrência, reformular se for instrução para LLM (não reformular se for descrição de comportamento humano ou documentação).
