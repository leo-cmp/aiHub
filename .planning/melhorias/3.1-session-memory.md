# 3.1 — session-memory.md

**Categoria:** Memória e Handoff | **Prioridade:** 🔴 Crítica | **Esforço:** S
**Fonte:** Ambas as análises

## Objetivo

Criar sistema de memória entre sessões próprio do aiHub, removendo dependência do ThreadBridge (ferramenta externa não controlada). O arquivo `.ai/session-memory.md` persiste estado da sessão para que um agente novo retome do ponto exato.

## Situação Atual

AGENTS.md:49-53:
```markdown
## Memoria do Projeto
No inicio de cada sessao, se a ferramenta ThreadBridge estiver disponivel,
carregue a memoria do projeto...
```

ThreadBridge é ferramenta externa sem garantia de disponibilidade. Sem ela, cada sessão começa do zero — o LLM precisa redescobrir o estado do projeto lendo arquivos.

### Mudanças no AGENTS.md

**Remover** o bloco atual:
```markdown
## Memoria do Projeto
No inicio de cada sessao, se a ferramenta ThreadBridge estiver disponivel...
```

**Adicionar** novo bloco:
```markdown
## Memória entre Sessões

No início de cada sessão:
1. Leia `.ai/session-memory.md`.
2. Se contiver task ativa e "Próximo Passo", retome de onde parou.
3. Confira se branch e task ainda são válidas (`git branch --show-current`).
4. Se o arquivo estiver vazio ou não existir, siga o fluxo normal de roteamento.

Ao final da sessão (ou quando contexto degradar — ver Context Canary):
1. Atualize `.ai/session-memory.md` com:
   - Task ativa e status
   - Branch atual
   - Último comando executado com exit code
   - Progresso (checklist do que foi feito/falta)
   - Pendências e bloqueios
   - Próximo passo prioritário
2. Atualize o cabeçalho com data/hora, agente e modelo.

Importante:
- Seja conciso. Máximo 50 linhas no total.
- Use checkboxes `[x]` / `[ ]` para progresso.
- Liste bloqueios com clareza para o próximo agente decidir.
```

### Atualizar `## Contexto Base`

Adicionar `session-memory.md` na lista:
```markdown
## Contexto Base

O contexto do projeto deve ser lido de:
1. `.ai/project.md`
2. `.ai/stack.md`
3. `.ai/guidelines/domain/business-rules/index.md`
4. `.ai/session-memory.md` (estado da última sessão)
5. `.ai/decisions.md` (decisões de arquitetura/stack/regras)
```

### Ciclo de Vida

| Momento | Ação | Gatilho |
|---------|------|---------|
| Início da sessão | Ler `.ai/session-memory.md` | AGENTS.md fluxo obrigatório |
| Handoff | Atualizar com estado completo | Context Canary detecta degradação |
| Fim de sessão normal | Atualizar com estado final | Usuário encerra ou task conclui |
| Ao concluir task | Atualizar progresso, apontar próxima | Executor termina task |
| Ao encontrar bloqueio | Registrar imediatamente | Bloqueio detectado |
