# 10.5 — Destino das Skills Fantasmas

**Categoria:** Skills — Criações | **Prioridade:** 🟡 Alta | **Esforço:** M
**Fonte:** DEEPSEEK

> Nota: A remoção das referências é feita no item 2.3. Este item (10.5) trata da decisão de criar ou não criar as skills que eram referenciadas.

## Objetivo

Decidir o destino final das 7 skills fantasmas: criar ou definitivamente remover.

## Decisão Final

| Skill | Decisão | Justificativa |
|-------|---------|---------------|
| `systematic-debugging` | ❌ Não criar | `execution.md` (Log de Evidências, Erros e Correções) já cobre debugging estruturado |
| `test-driven-development` | ❌ Não criar | `testing.md` + `execution.md` cobrem. TDD é prática, não skill |
| `writing-plans` | ❌ Não criar | `criar-plano` + `planning.md` cobrem. `brainstorming` referenciava como next step |
| `requesting-code-review` | ❌ Não criar | `revisar` (item 10.1) + `git-pr.md` cobrem auto-review e PR |
| `receiving-code-review` | ❌ Não criar | Revisão de PR recebido é coberta por `qa-release-engineer` + `git-pr.md` |
| `finishing-a-development-branch` | ❌ Não criar | `execution.md` checklist de PR cobre encerramento de branch |
| `verification-before-completion` | ❌ Não criar | `execution.md` checklist de encerramento (item 4.1) cobre verificação |

**Conclusão: Nenhuma das 7 será criada.** As funcionalidades que elas cobririam já existem em guidelines existentes ou em novas skills mais enxutas (`revisar`).

## Ações

Todas as ações de remoção estão no item 2.3. Este arquivo serve como registro da decisão para referência futura — se alguém perguntar "por que não criamos `writing-plans`?", a resposta está aqui.
