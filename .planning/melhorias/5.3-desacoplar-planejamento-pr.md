# 5.3 — Desacoplar Planejamento de PR

**Categoria:** Integração com GitHub | **Prioridade:** 🟡 Alta | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Permitir que tarefas de planejamento existam sem issue no GitHub. `planning.md:8` exige que "toda task local deve ter issue GitHub antes de ir para execução". Isso bloqueia planejamento offline ou quando `gh` CLI não está disponível.

## Situação Atual

`planning.md:20`:
```markdown
- Toda task local deve ter issue GitHub antes de ir para execucao, salvo bloqueio explicito.
```

Isso é correto para tasks de execução (que vão gerar PR), mas incorreto para tasks de planejamento (que só produzem arquivos `.md`).

## Especificação

### Mudança em planning.md

Alterar a linha 20:

```markdown
# Antes:
- Toda task local deve ter issue GitHub antes de ir para execucao, salvo bloqueio explicito.

# Depois:
- Toda task EXECUTAVEL (que gera codigo/PR) deve ter issue GitHub antes da execucao.
- Tasks de planejamento (que apenas produzem documentacao/planos) podem existir sem issue.
- Se `gh` CLI nao estiver disponivel, crie a issue como `.planning/PLAN_VN/issues/issue_X.md` localmente e sincronize depois com `scripts/sync-github.sh`.
```

### Mudança em executar-task

`executar-task/SKILL.md:18`:
```markdown
- Confirme que existe issue GitHub vinculada (campo `issue` no cabecalho).
```

Alterar para:

```markdown
- Se a task for EXECUTAVEL (gera codigo/PR), confirme que existe issue GitHub vinculada.
- Se for task de planejamento, o campo `issue` pode estar vazio ou conter link para arquivo local.
```

## Arquivos Afetados

- `src/.ai/guidelines/core/planning.md`: ajustar linha sobre issue obrigatória
- `src/.agents/skills/executar-task/SKILL.md`: ajustar validação de issue

## Critérios de Aceite

- [ ] `planning.md` distingue task executável de task de planejamento
- [ ] `planning.md` permite task de planejamento sem issue
- [ ] `planning.md` referencia fallback local (`issues/issue_X.md`)
- [ ] `executar-task` não bloqueia task de planejamento por falta de issue
