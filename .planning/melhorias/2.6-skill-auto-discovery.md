# 2.6 — Skill Auto-Discovery nas Roles

**Categoria:** Robustez do Sistema de Regras | **Prioridade:** 🟢 Média | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Adicionar instrução no AGENTS.md para que o LLM verifique se as skills listadas na role existem antes de tentar carregá-las. Se não existirem, reportar ao invés de tentar carregar skill fantasma.

## Situação Atual

Roles listam skills na seção `## Skills`. Se uma skill não existe no diretório, o LLM tenta carregar e falha silenciosamente ou com comportamento imprevisível.

## Especificação

### Mudança no AGENTS.md

Adicionar no `## Fluxo Obrigatorio`, no passo que lê a role:

```markdown
4. Leia somente as guidelines indicadas pelo cargo ou pela demanda.
5. Verifique as skills listadas na role: para cada skill, confirme que o diretorio existe em `.agents/skills/<skill>/`.
   - Se existir: carregue quando necessario.
   - Se NAO existir: ignore a skill (nao tente carregar) e mencione no inicio da execucao: "Role referencia skill `<skill>` que nao existe no projeto."
```

### Complemento: validate.sh

O script `validate.sh` (item 2.2) já detecta skills referenciadas mas inexistentes. A auto-discovery é a defesa em runtime; o validate.sh é a defesa em tempo de desenvolvimento.

## Arquivos Afetados

- `src/AGENTS.md`: adicionar verificação de skills no fluxo obrigatório
