# 4.4 — Test Relevance Check

**Categoria:** Verificação e Anti-Alucinação | **Prioridade:** 🟢 Média | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Antes de considerar os testes como prova de que a implementação funciona, verificar que pelo menos 1 teste cobre explicitamente o código alterado. Evita "testes passam com exit 0 mas não testam nada relacionado à task".

## Especificação

### Mudança no execution.md

Adicionar no `## Checklist de Encerramento` (item 4.1), expandindo o item "Testes relacionados passam":

```markdown
- [ ] Testes passam (`exit 0`)
- [ ] **Test relevance check:** Pelo menos 1 teste cobre explicitamente o código alterado.
  - Confirme que o teste referencia: nome do metodo alterado, rota modificada, ou model/entidade da task.
  - Use `grep` para buscar referencias nos arquivos de teste.
  - Se nenhum teste cobrir: NAO marque como verificado. Adicione teste ou marque como `⚠️ Nao verificado`.
```

### Exemplo

```bash
# Task: alterou SupplierController::update()
grep -r "SupplierController\|update.*supplier\|supplier.*update" tests/
# Se retornar vazio → nenhum teste cobre → marcar como ⚠️ Nao verificado
```

## Arquivos Afetados

- `src/.ai/guidelines/core/execution.md`: expandir item do checklist

## Critérios de Aceite

- [ ] Checklist de encerramento inclui test relevance check
- [ ] Instrução para usar `grep` nos arquivos de teste
- [ ] Se nenhum teste cobrir: marcar como não verificado
- [ ] Não bloqueia conclusão da task, mas força transparência (⚠️ em vez de [x])
