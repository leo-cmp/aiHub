# 4.5 — Log de Evidências com Resumo

**Categoria:** Verificação e Anti-Alucinação | **Prioridade:** 🟢 Média | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Melhorar o formato do Log de Evidências para comandos com saída longa. Em vez de `comando → saída completa`, usar `comando → exit code (resumo 1 linha)`. Saída completa vai para arquivo anexo se necessário.

## Situação Atual

`execution.md:39`:
```
* YYYY-MM-DD HH:mm - [Acao: comando → saida (exit code)]
```

Isso assume saída curta. Para migrations com 50 tabelas ou testes com 200 asserts, o log fica ilegível.

## Especificação

### Mudança no execution.md

Alterar o formato de evidência:

```markdown
## Registro de Evidencias (Anti-Alucinacao)

Toda afirmacao de "fiz", "corrigi", "implementei" ou "funciona" DEVE ter prova.

Prova = comando executado + exit code + resumo (1 linha).

Formato no Log de Evidencias da task:
* YYYY-MM-DD HH:mm - [Acao] `comando` → exit 0 | Resumo: 42 tests passed, 0 failed

Se a saida for longa (>10 linhas), salve em `.planning/PLAN_VN/evidencias/task_X_Y_step_N.log` e referencie no log:
* YYYY-MM-DD HH:mm - [Acao] `comando` → exit 0 | Ver saida completa: `.planning/PLAN_VN/evidencias/task_1_2_step_3.log`
```

### Mudança no template task.md

Atualizar o exemplo de formato na seção `## Log de Evidencias`:

```markdown
* YYYY-MM-DD HH:mm - [Acao: comando → exit code | Resumo 1 linha]
* YYYY-MM-DD HH:mm - [Acao: comando → exit code | Saida longa: ver arquivo anexo]
```

## Arquivos Afetados

- `src/.ai/guidelines/core/execution.md`: atualizar formato de evidência
- `src/.ai/templates/task.md`: atualizar exemplo de formato

## Critérios de Aceite

- [ ] Formato de evidência inclui resumo de 1 linha (não saída bruta)
- [ ] Saídas longas (>10 linhas) vão para arquivo `.planning/.../evidencias/`
- [ ] Template `task.md` atualizado com novo formato
- [ ] Exemplos no `execution.md` refletem o novo formato
