# 11.3 — Migrar Assets para src/

**Categoria:** Distribuição e Instalação | **Prioridade:** 🟡 Alta | **Esforço:** M
**Fonte:** DEEPSEEK

## Objetivo

Mover todos os assets instaláveis para `src/`. A raiz do repo fica só com `scripts/`, `docs/`, README, INSTALL, VERSION. `install.sh` lê de `src/` e instala no projeto alvo. aiHub nunca se instala em si mesmo.

## Situação Atual

Estrutura atual (raiz):
```
aiHub/
├── AGENTS.md         ← vai pra src/
├── CLAUDE.md         ← symlink de AGENTS.md, vai pra src/
├── .agents/          ← vai pra src/
├── .ai/              ← vai pra src/
├── .mcp.json         ← vai pra src/
├── .threadbridge/    ← fica (não é instalável)
├── .claude/          ← fica (config local do dev)
├── .junie/           ← fica

├── .git/             ← fica

├── docs/             ← fica

├── README.md          ← fica

```

## Especificação

### Passo 1: Criar src/

```bash
mkdir -p src
```

### Passo 2: Mover assets

```bash
mv AGENTS.md src/AGENTS.md
mv CLAUDE.md src/AGENTS.md  # ou remover (CLAUDE.md é symlink)
mv .agents src/.agents
mv .ai src/.ai
mv .mcp.json src/.mcp.json
```

### Passo 3: Ajustar caminhos internos

Arquivos dentro de `src/` que referenciam outros arquivos do aiHub precisam de ajuste de path. Exemplo: `AGENTS.md` referencia `.ai/roles/index.md` — continua funcionando porque o path é relativo ao projeto alvo após instalação.

**Verificar:** `grep -r "\.agents\|\.ai/" src/` para garantir que referências internas continuam válidas após mover para `src/`.

**Prováveis ajustes:**
- `AGENTS.md` referências a `.ai/` e `.agents/` — OK, paths relativos ao alvo
- `install.sh` — atualizar paths fonte: `src/AGENTS.md`, `src/.ai/`, `src/.agents/`, `src/.mcp.json`

### Passo 4: Atualizar install.sh

Já especificado no item 11.1 com paths apontando para `src/`.

### Passo 5: Limpar raiz

Garantir que nenhum arquivo leftover fique:
```bash
# Remover symlinks obsoletos
rm -f CLAUDE.md CODEX.md COPILOT.md ANTIGRAVITY.md 2>/dev/null || true
```
