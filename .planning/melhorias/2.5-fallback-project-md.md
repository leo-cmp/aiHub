# 2.5 — Fallback para project.md Inexistente

**Categoria:** Robustez do Sistema de Regras | **Prioridade:** 🟡 Alta | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Adicionar fallback explícito no AGENTS.md para quando `.ai/project.md` não existe. Atualmente o arquivo é referenciado em 12+ lugares mas nunca foi criado no repositório aiHub.

## Situação Atual

O problema é que o LLM recebe instrução "leia `.ai/project.md`", tenta, recebe erro "file not found", e o comportamento é imprevisível dependendo do modelo:
- Claude: reporta erro (bom)
- GPT-5: pode assumir defaults (perigoso)
- Gemini: pode ignorar (perigoso)

## Especificação

### Mudança 1: AGENTS.md — Tabela de Roteamento

Adicionar na tabela de roteamento a entrada existente já cobre isso parcialmente:
```
| Qualquer agente | `.ai/project.md` nao existe... | `project-planner` |
```

Mas o LLM pode não chegar a consultar a tabela se seguir o fluxo obrigatório diretamente. Corrigir adicionando um gate no início do `## Fluxo Obrigatorio`:

```markdown
## Fluxo Obrigatorio

0. **Gate inicial:** Verifique se `.ai/project.md` existe.
   - Se NÃO existir: ignore o resto do fluxo. Assuma o cargo `project-planner`.
   - Se existir: prossiga para o passo 1.

1. Identifique a natureza da demanda atual.
...
```

### Mudança 2: Remover da cadeia de prioridade

Com o item 2.1 (eliminar hierarquia), a linha "Se `.ai/project.md` nao existir, a entrada `project-planner` vence" já some naturalmente. O gate no fluxo cobre o caso.

## Arquivos Afetados

- `src/AGENTS.md`: adicionar passo 0 no `## Fluxo Obrigatorio`

## Critérios de Aceite

- [ ] AGENTS.md `## Fluxo Obrigatorio` começa com passo 0 verificando `project.md`
- [ ] Passo 0 instrui: se não existir → `project-planner`, ignorar resto do fluxo
- [ ] Passo 0 instrui: se existir → prosseguir normalmente
- [ ] Não há referência ambígua a `project.md` sem fallback definido
