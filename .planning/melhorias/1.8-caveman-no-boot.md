# 1.8 — Caveman Carregado no Boot

**Categoria:** Tokenomia e Contexto | **Prioridade:** 🔴 Crítica | **Esforço:** S
**Fonte:** Ambas as análises

## Objetivo

Carregar a skill `caveman` junto com a role (não lazy). 400 tokens de overhead que se pagam na 2ª ou 3ª resposta longa da sessão. A skill já está em `.agents/skills/caveman/` do próprio aiHub — não depende do projeto ter.

## Situação Atual

AGENTS.md linha 12: "Sempre use a skill 'caveman' se disponivel no projeto — carregue-a antes de escrever respostas longas."

Problema: lazy loading com gatilho "antes de escrever respostas longas" é impossível de executar — o LLM não sabe o comprimento da resposta antes de escrevê-la. Resultado: caveman nunca carrega.

## Especificação

### Mudança 1: AGENTS.md

Remover a linha do lazy loading. Adicionar no `## Fluxo Obrigatorio`:

```markdown
## Fluxo Obrigatorio

1. Identifique a natureza da demanda atual.
2. Leia `.ai/roles/index.md`.
3. Leia apenas o arquivo do cargo aplicavel.
4. Leia somente as guidelines indicadas pelo cargo ou pela demanda.
5. Carregue a skill `caveman` (`.agents/skills/caveman/SKILL.md`) — ela está no próprio aiHub.
```

### Mudança 2: Seção de Carregamento de Skills

Remover a menção ao caveman do bloco `## Carregamento de Skills (Lazy Loading)`:

Antes:
```markdown
**Nao carregue skills antecipadamente.** A unica skill universal e `caveman`...
```

Depois:
```markdown
**Nao carregue skills antecipadamente.**
```

### Regra de segurança

Caveman já tem auto-clareza embutida (SKILL.md:58-77): desliga automaticamente para warnings de segurança, operações irreversíveis e quando compressão gera ambiguidade. Nenhuma mudança necessária na skill.

Com os circuit breakers (máx 5 skills por sessão, item 6.1), caveman ocupa 1 slot — sobram 4 para skills de domínio.
