# 4.3 — Sanity Check Pré-Execução

**Categoria:** Verificação e Anti-Alucinação | **Prioridade:** 🟡 Alta | **Esforço:** M
**Fonte:** DEEPSEEK

## Objetivo

Antes de iniciar a implementação de uma task, verificar que todas as entidades mencionadas (tabelas, models, rotas, componentes) existem no código base. Se alguma não existir, a task é inválida e precisa ser revisada. Previne "implementei contra um schema que não existe".

## Especificação

### Mudança no executar-task

Adicionar passo `2.5` entre "Validar a task" e "Preparar execução":

```markdown
2.5. **Sanity check (pré-execução):**
   - Liste todas as entidades mencionadas na task: tabelas, models, rotas, controllers, views, componentes.
   - Para cada entidade:
     - Se a task diz "alterar" ou "usar" a entidade → verifique que ela EXISTE no codigo base.
     - Se a task diz "criar" a entidade → verifique que ela NAO existe ainda (evitar duplicacao).
   - Use `grep`, `find` ou leitura de diretorio para confirmar.
   - Se alguma verificacao falhar:
     - Registre o problema.
     - PARE. Nao implemente.
     - Informe o usuario: "Entidade X referenciada na task nao existe no codigo. Task precisa ser revisada."
   - Se todas passarem: prossiga para o passo 3.
```

### Exemplos de verificações

| Task diz | Verificar | Comando |
|----------|-----------|---------|
| "Alterar model User" | Model User existe? | `find app/Models -name "User.php"` |
| "Adicionar rota /api/products" | Rota já existe? | `grep -r "api/products" app/Config/Routes.php` |
| "Criar migration CreateOrders" | Migration já existe? | `find app/Database/Migrations -name "*CreateOrders*"` |
| "Usar componente Badge" | Componente existe? | `find app/Views/components -name "Badge.php"` |
