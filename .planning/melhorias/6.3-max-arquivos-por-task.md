# 6.3 — Máx 10 Arquivos por Task

**Categoria:** Guardrails Quantitativos | **Prioridade:** 🟡 Alta | **Esforço:** S
**Fonte:** DEEPSEEK

## Objetivo

Limitar o escopo de uma task a 10 arquivos modificados. Acima disso, a task deve ser quebrada em sub-tasks. Previne refactors em cascata e mantém PRs revisáveis.

## Especificação

Adicionar ao `AGENTS.md`, no bloco `## Fluxo Obrigatorio` ou `## Níveis de Complexidade`:

```markdown
**Limite de escopo:** Nenhuma task deve modificar mais de 10 arquivos.
Se a implementação exigir mais:
- Quebre em sub-tasks menores.
- Cada sub-task deve ter seu proprio criterio de aceite e PR.
- Tasks L3 (complexas) naturalmente exigem quebra — nunca implemente L3 como task unica.
```

Adicionar no `planning.md`:

```markdown
- Ao criar task, verifique se o escopo estimado ultrapassa 10 arquivos.
  Se sim, quebre em sub-tasks antes de criar a task.
- O campo `Plano de Execucao` da task deve listar os arquivos esperados.
```

## Arquivos Afetados

- `src/AGENTS.md`: adicionar limite de escopo
- `src/.ai/guidelines/core/planning.md`: adicionar verificação de escopo

## Critérios de Aceite

- [ ] AGENTS.md especifica máximo de 10 arquivos por task
- [ ] AGENTS.md instrui quebrar em sub-tasks se ultrapassar
- [ ] `planning.md` verifica escopo estimado antes de criar task
- [ ] Tasks L3 explicitamente exigem quebra
