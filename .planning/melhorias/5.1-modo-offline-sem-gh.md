# 5.1 — Modo Offline sem `gh` CLI

**Categoria:** Integração com GitHub | **Prioridade:** 🔴 Crítica | **Esforço:** M
**Fonte:** DEEPSEEK

## Objetivo

Permitir que o sistema funcione sem `gh` CLI instalado. Issues são criadas como arquivos locais e sincronizadas depois com `scripts/sync-github.sh`.

## Situação Atual

`planning.md:12` exige criação automática de milestone/issue via `gh`. Se `gh` falhar (token expirado, rate limit, não instalado), o sistema para.

## Especificação

### Mudança 1: planning.md

Adicionar fallback offline:

```markdown
- **Criacao de issues offline:** Se `gh` CLI nao estiver disponivel ou falhar:
  1. Crie a issue como arquivo local: `.planning/PLAN_VN/issues/issue_X.md`
  2. Formato do arquivo: copie o corpo da issue (titulo, descricao, criterios, contexto tecnico)
  3. No campo `issue:` do cabecalho da task, preencha com o caminho local: `issue: .planning/PLAN_VN/issues/issue_X.md`
  4. Marque a task como `⚠️ issue pendente de sincronizacao com GitHub`
  5. Quando `gh` estiver disponivel, rode `scripts/sync-github.sh` para criar as issues no GitHub
- **Criacao de milestones offline:** Mesmo principio. Crie `.planning/PLAN_VN/milestone.md` localmente.
```

### Mudança 2: Modelo de issue local

Criar template `.ai/templates/issue-local.md`:

```markdown
---
title: "[Task X.Y] Titulo descritivo"
milestone: "VN - Nome da fase"
created_at: YYYY-MM-DD
github_issue: null
---

# [Task X.Y] Titulo descritivo

## Historia
Como [persona], quero [acao], para [beneficio].

## Criterios de Aceite
- [ ] Criterio 1

## Contexto Tecnico
- Plano: `.planning/PLAN_VN/plan.md`
- Task local: `.planning/PLAN_VN/tasks/task_X_Y.md`
- Modelo recomendado: [modelo]
- Cargo: [cargo]
```

### Mudança 3: executar-task

Ajustar validação:

```markdown
# Antes:
- Confirme que existe issue GitHub vinculada (campo `issue` no cabecalho).

# Depois:
- Confirme que existe issue vinculada (GitHub ou local).
- Se for issue local (`issue: .planning/...`), a task pode prosseguir.
- Se for task executavel sem issue alguma, pare e crie a issue primeiro.
```
